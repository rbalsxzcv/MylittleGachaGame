# Tiny Gacha 개발 도구 (로컬 전용)

내 컴퓨터에서만 실행하는 관리 도구예요. 다음 일을 할 수 있어요.

- 캐릭터 그림을 AI로 만들고, 배경을 지우고, 마음에 들 때까지 고치기
- 배너, 스토리, 공지, 우편 만들기
- 일정 확인, 검사, GitHub에 배포하기

> 개발 도구는 `127.0.0.1`(내 컴퓨터)에서만 열려요. GitHub Pages로 배포되는 게임에는 포함되지 않아요.

---

## 1. 처음 한 번만: 설치

### 1-1. Python 설치
[python.org](https://www.python.org/downloads/)에서 Python 3.11 이상을 설치해요.
설치 화면에서 **"Add python.exe to PATH"를 꼭 체크**하세요.

### 1-2. 가상환경(venv) 만들기
가상환경은 이 프로젝트 전용 파이썬 패키지 상자예요. 컴퓨터 전체를 어지럽히지 않아요.
VS Code 터미널(PowerShell)을 열고 저장소 폴더에서 다음을 실행해요.

```powershell
cd dev
py -m venv .venv              # 가상환경 만들기 (dev/.venv 폴더가 생김, git에는 안 올라감)
.venv\Scripts\Activate.ps1    # 가상환경 켜기 → 줄 앞에 (.venv)가 보이면 성공
pip install -r requirements.txt
```

`Activate.ps1`에서 "스크립트를 실행할 수 없습니다" 오류가 나면 아래를 한 번 실행한 뒤 다시 켜세요.

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

macOS/Linux는 `python3 -m venv .venv`로 만들고 `source .venv/bin/activate`로 켜요.

### 1-3. (선택) BRIA RMBG 배경 제거 설치
설치하지 않아도 **간단 모드**(흰 배경 지우기)로 동작해요. 머리카락 같은 섬세한 부분까지 깔끔하게 지우려면 설치하세요.
용량이 커요(수 GB).

```powershell
pip install -r requirements-rmbg.txt
```

- 기본 모델은 [briaai/RMBG-2.0](https://huggingface.co/briaai/RMBG-2.0)이에요. Hugging Face 계정으로 모델 페이지에서 라이선스에 동의한 뒤, [토큰](https://huggingface.co/settings/tokens)을 `.env`의 `HF_TOKEN`에 넣어요.
- RMBG는 **비상업 라이선스**예요. 이 프로젝트는 비상업이라 괜찮지만, 상업적으로 쓰려면 BRIA와 별도 계약이 필요해요.
- 2.0이 잘 안 되면 `.env`에 `TG_RMBG_MODEL=briaai/RMBG-1.4`를 넣어 보세요.

### 1-4. Vertex AI 키 설정
키가 없어도 **모의(MOCK) 모드**로 모든 흐름을 연습할 수 있어요. 이때는 가짜 그림과 글이 나와요.

1. [Google Cloud 콘솔](https://console.cloud.google.com/)에서 프로젝트를 만들고 **Vertex AI API**를 켜요.
2. IAM → 서비스 계정을 만들고 역할 **Vertex AI 사용자**를 줘요. 그다음 **키 → JSON 키 만들기**로 파일을 받아요.
3. 키 파일은 **저장소 밖**(예: `C:\Users\내이름\keys\`)에 두세요. 절대 커밋하지 마세요.
4. `dev/.env.example`을 복사해서 `dev/.env`로 이름을 바꾸고 값을 채워요.
   ```
   GOOGLE_CLOUD_PROJECT=내-프로젝트-id
   GOOGLE_CLOUD_LOCATION=global
   GOOGLE_APPLICATION_CREDENTIALS=C:\Users\내이름\keys\tinygacha-vertex.json
   ```
   `.env`는 `.gitignore`에 들어 있어서 GitHub에 올라가지 않아요. 키 경로와 내용은 코드나 화면 어디에도 표시되지 않아요.

기본 모델은 다음과 같아요. `.env`에서 바꿀 수 있어요.
- 이미지: `gemini-nano-banana-2.1` (지금은 쓰지 않아요. 그림은 ComfyUI로만 그려요)
- 텍스트: `gemini-3.8-flash`

모델 이름은 바뀔 수 있으니, 오류가 나면 [Vertex 이미지 생성 문서](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/multimodal/image-generation)와 [모델 버전 문서](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/learn/model-versions)에서 최신 이름을 확인하세요.
AI 호출에는 Google Cloud 요금이 나와요. 거절하고 다시 생성할 때마다 한 번씩 과금돼요.
그림은 ComfyUI로 그리지만 **프롬프트 작성(Gemini)**에는 Vertex 키를 써요. 키가 없으면 에셋 종류별 기본 태그로 프롬프트를 만들어요.

### 1-5. ComfyUI 연결 (그림 생성)
모든 그림은 내 PC의 [ComfyUI](https://github.com/comfyanonymous/ComfyUI)로 그려요. 프롬프트는 Anima 모델에 맞춰 써요.
1. ComfyUI를 설치하고 모델 파일을 넣어요. 모델 종류에 따라 두 가지 방식이 있어요.
   - **체크포인트 한 파일** (SDXL, SD1.5 등): `ComfyUI/models/checkpoints/` 에 넣어요. 애니메이션 스타일 SDXL 계열을 추천해요.
   - **따로 나뉜 파일** (Anima / Anima Turbo, Flux 등 확산 모델): 확산 모델은 `models/diffusion_models/`, 텍스트 인코더는 `models/text_encoders/`, VAE는 `models/vae/` 에 넣어요. 설정 탭에서 **모델 불러오기 방식**을 "따로"로 바꾸고 세 파일과 **텍스트 인코더 종류**(CLIPLoader type)를 골라요. Anima 예: `qwen_3_06b_base` + `qwen_image_vae`, 종류 `stable_diffusion`. Turbo 모델은 CFG 1, 스텝 8~12 정도로 맞춰요.
2. ComfyUI를 실행해요. 기본 주소는 `http://127.0.0.1:8188`예요.
3. 개발 도구의 **설정 탭**에서 아래 순서로 진행해요.
   1. ComfyUI 주소를 넣고 **연결 확인**을 눌러요.
   2. 모델 파일을 고르고, 해상도 기준(SDXL / SD1.5), 스텝, CFG, 샘플러, 품질 태그를 정한 뒤 저장해요.
      Anima는 약 100만 픽셀(1024 기준)로 학습돼서 **SDXL 기준**이 가장 잘 나와요. SD1.5 기준은 빠르지만 디테일이 줄어요.
      CFG가 1(Turbo)이면 네거티브 프롬프트는 적용되지 않아요.

개발 도구에 기본 워크플로(모델 불러오기 → 프롬프트/네거티브 → KSampler → 저장)가 들어 있어서 ComfyUI에서 따로 만들 필요가 없어요.
기본 워크플로는 참고 이미지를 쓰지 않아요. 대신 배너를 그릴 때 픽업 캐릭터 그림을 만들 때 쓴 외형 태그를 이어받아서 모습을 맞춰요.

화면 위쪽에서 상태를 확인할 수 있어요: **그림: ComfyUI · 모델**, **일괄 생성 진행 상황**(진행 중일 때), **Gemini: 모델 / 모의 모드**, **배경 제거: RMBG / 간단 모드**, **git 브랜치**.

## 3. 작업 흐름

### 작업 공간 → 배포
개발 도구에서 고친 내용은 먼저 **`dev/workspace/`**(작업 공간)에 저장돼요. 이 폴더는 git에 올라가지 않아요.
저장소가 공개라서, 아직 공개하지 않은 캐릭터나 스토리가 GitHub에 올라가면 스포일러가 되기 때문이에요.

**배포 탭**에서 아래 순서로 게임에 반영해요.
1. 검사
2. 보류 확인
3. 패치노트 작성
4. 배포하기 (공개 폴더 `data/`, `assets/`에 반영)
5. git push

### 그림 뽑기 공통 (캐릭터 · 배너 · 스토리 배경 · UI 에셋)
1. **AI로 프롬프트 쓰기**를 누르면 Gemini가 입력한 설정을 읽고 Anima용 프롬프트(영어 태그 + 짧은 문장, 네거티브)를 써요.
   에셋 종류마다 규칙이 달라요.
   - 캐릭터: 배경 없는 흰 배경, 머리부터 신발까지 전신, 성격과 역할에 맞는 포즈와 표정, 소품 하나. 배경 제거가 깔끔하도록 효과는 몸 가까이 조금만.
   - 배너: 픽업 캐릭터만, 인원수 태그 일치, 캐릭터는 오른쪽 · 왼쪽 아래는 제목 자리로 비움, 이벤트에 맞는 배경. 글자는 그리지 않아요.
   - 스토리 배경: 인물 없는 풍경, 장소 · 시간 · 날씨, 가운데와 아래쪽(대화창 자리)은 단순하게.
   - 화면 배경: 인물 없는 풍경, 칸 설명의 배치(어느 쪽을 비울지)를 지키고 대비를 낮게.
   - 아이콘: 물체 하나, 가운데, 굵은 외곽선, 작게 봐도 알아보게, 흰 배경.
   - 로고: 가운데 대칭 엠블럼, 흰 배경. Anima는 글자를 잘 못 그려서 빈 리본으로 만들어요.
   - 나온 프롬프트를 보고 고쳐도 돼요.
   **용도별 필수 / 금지 태그는 자동으로 강제돼요** (AI가 쓴 것이든 직접 고친 것이든). CFG 1(Turbo)에서는 네거티브가 무시되기 때문이에요.
   - 캐릭터: 맨 앞에 `1girl/1boy, solo, full body, standing`, 끝에 "한 캐릭터를 한 번만" 문장. `multiple views`, `reference sheet`, `concept art`, `turnaround`, `back view`, `2girls` 같은 설정화 태그는 빠져요. 그림 비율은 세로로 긴 2:3이에요.
   - 배경 · 화면 배경: 맨 앞에 `no humans, scenery`. 사람을 부르는 태그와 문장(girl, people, shopkeeper, character …), UI · 글자 이야기는 빠져요.
   - 아이콘 · 로고: 맨 앞에 `no humans, object focus` / `no humans, emblem`. 사람, 손이 나오는 태그는 빠져요.
   - 뺀 태그는 결과 화면에 "용도에 안 맞는 태그를 뺐어요"로 보여요.
   **캐릭터 자동 검사**: 배경을 지운 뒤, 떨어진 인물이 2개 이상이거나(정면+후면 설정화, 여러 명) 그림이 가로로 넓으면 "자동 검사" 경고를 띄워요. 일괄 생성에서는 새 seed로 최대 2번 다시 뽑고, 그래도 걸리면 바로 적용하지 않고 검토로 남겨요.
2. 실제로 보내는 프롬프트: **품질 태그**(설정) → 용도별 필수 태그 → 핵심 프롬프트 → 공통 스타일. 네거티브: AI가 쓴 것 → 에셋 종류별 기본 → 설정의 기본 네거티브. 같은 태그는 한 번만 들어가요.
3. **그림 뽑기**를 누르면 그려요. 프롬프트를 먼저 쓰지 않고 바로 눌러도 돼요. 그러면 AI가 쓰고 곧바로 그려요.
4. 결과를 검사해요.
   - **승인(통과)**: 에셋으로 저장해요.
   - **거절 + 사유**: Gemini가 이전 프롬프트와 지금까지의 거절 사유를 모두 반영해서 프롬프트를 고친 뒤 다시 뽑아요.
   - **같은 프롬프트로 다시 뽑기**: 프롬프트는 그대로 두고 새로 뽑아요(새 seed).
   - **프롬프트 직접 고쳐서 다시 생성**: 프롬프트와 네거티브를 직접 고쳐서 뽑아요.
   - 시도마다 seed, 프롬프트 출처(Gemini 작성 / 직접 수정)가 기록돼요.
- 공통 스타일 문구는 생성할 때 항상 뒤에 붙어요.
  - 캐릭터: `dev/style.txt`
  - 배너: `style_banner.txt`
  - 배경: `style_bg.txt`
  - 아이콘: `style_icon.txt`
- 설정 탭에서 "Gemini가 그림 프롬프트를 작성"을 끄면, 에셋 종류별 기본 태그에 입력값을 붙여서 프롬프트로 써요.

### 일괄 생성 (일괄 생성 탭)
그림이 필요한 항목(캐릭터 · 배너 · 화면 배경 · 로고 · 아이콘)을 한 번에 뽑아요.
1. 뽑을 항목을 골라요. 처음에는 **그림이 없는 항목**이 골라져 있어요. 이미 있는 것도 골라서 다시 뽑을 수 있어요.
2. 옵션을 정하고 **일괄 생성 시작**을 눌러요.
   - **공통 추가 요청**: 모든 항목 프롬프트에 함께 들어가요.
   - **뽑은 그림을 바로 게임에 적용**: 끄면(기본) 끝난 뒤 목록에서 **검토 · 적용**으로 하나씩 보고 적용해요. 거절이나 다시 뽑기도 할 수 있어요. **적용 안 한 결과 모두 적용**도 있어요.
   - **오류가 나면 거기서 멈추기**: 끄면 오류 항목은 건너뛰고 계속해요. ComfyUI 연결 오류는 항상 멈춰요.
3. 캐릭터부터 차례로 하나씩 그려요. 그래서 배너는 방금 그린 캐릭터의 외형을 이어받아요. 다른 탭으로 가도 계속 진행되고, 화면 위에 진행 상황이 보여요.
4. 오류가 나면 바로 알림이 뜨고, 목록에 항목별 오류 내용이 남아요.
5. **중단**을 누르면 지금 그리는 ComfyUI 작업도 멈추고 남은 항목은 뽑지 않아요. 이미 끝난 결과는 그대로 남아요.
- 결과는 항목마다 생성 작업 기록(`dev/history/`)에 남아요. 서버를 껐다 켜면 일괄 생성 목록은 사라지지만, 그림은 각 탭의 작업 기록에서 다시 볼 수 있어요.

### 캐릭터 만들기 (캐릭터 탭)
1. 이름, 희귀도, 칭호, 외형 키워드, 설정 메모를 입력하고 그림을 뽑아요. 방법은 위의 공통 단계와 같아요.
2. 오른쪽에서 결과를 비교해요. 원본, 배경 제거본(체크무늬 배경), 배경 제거본(어두운 배경)이 나란히 보여요.
3. 결과에 따라 버튼을 골라요.
   - **승인 → 캐릭터 추가**: id(예: `ssr_lumi`)와 소개문을 정하면 `assets/chars/<id>.png`와 `characters.json`에 저장돼요. 이 그림으로 **신캐릭터**가 만들어져요. 소개문은 "AI로 소개문 쓰기"로 만들 수 있어요.
   - **거절 / 다시 뽑기**: 위의 공통 단계와 같아요.
   - **배경 제거만 다시 하기**: 같은 원본을 써요. 배경이 얼룩덜룩하면 "먼저 단색으로 칠하기"를 체크해요.
4. 모든 시도는 `dev/history/<작업id>/`에 남아요. 원본, 결과, 프롬프트, 거절 사유가 저장되고, "두 시도 비교"로 나란히 볼 수 있어요.
5. 기존 캐릭터는 **정보 수정**, **그림 교체**, **삭제**를 할 수 있어요. 삭제 전에는 어디서 쓰이는지 알려줘요.
- **공개 시각(addedAt)** 전에는 게임에 나오지 않아요. 픽업 배너 시작 시각과 맞추면 "신규 캐릭터 데뷔"가 돼요.
- 공통 스타일 문구는 `dev/style.txt`에 있어요. 배너는 `style_banner.txt`, 배경은 `style_bg.txt`예요.

### 배너 (배너 탭)
- 픽업 캐릭터와 기간(한국 시간)을 정해요. 이벤트 스토리를 연결할 수 있어요.
- **키 아트 생성**: 픽업 캐릭터의 그림을 참고 이미지로 보내서 16:9 그림을 만들어요. 승인, 거절, 다시 생성은 캐릭터와 같아요.
- **게임 화면으로 미리보기**: 실제 게임에서 그 배너의 상세 화면을 띄워요. 미래 배너면 그 시각으로 시간을 옮겨서 보여줘요.

### 스토리 (스토리 탭)
- 종류별(메인/캐릭터/이벤트) 목록에서 ▲▼로 순서를 바꾸면 장 번호가 다시 매겨져요.
- 장면마다 배경(색 또는 그림)과 대사 목록이 있어요.
  - 대사마다 화자, 표시 이름(예: ???), 자리(왼쪽/오른쪽)를 정할 수 있어요.
  - 선택지(최대 4개)는 장면으로 이동해요.
  - 갈라진 장면은 **끝나면 →** 으로 다시 합류시켜요.
- **세계관 · 문체** (스토리 탭 왼쪽 아래): 세계, 장소, 세력, 규칙, 큰 줄거리를 적어 두면 AI가 모든 장을 쓸 때 먼저 읽어요.
  - `dev/story_bible.json`에 저장돼요. 앞으로의 줄거리가 들어가기 쉬워서 **git에 올라가지 않아요** (작업 공간 초기화에도 지워지지 않음). 따로 백업해 두세요.
- **AI로 이 장 만들기**: 이번 장의 대략적인 줄거리(예: "주인공이 사막 도시로 떠나 모래 폭풍에 갇힌 대상을 돕는다")만 적으면 AI가 알맞은 분량의 대본을 써요.
  - 분량: AI가 판단(기본) / 짧게 / 보통 / 길게
  - AI가 함께 읽는 것: 세계관 + 같은 묶음 **앞 장들의 요약** + **직전 장 대본 전체** (말투, 마지막 상황, 호칭을 이어받음)
  - 등장 캐릭터를 고르지 않으면 등록된 캐릭터 전체를 알려 줘요. 목록에 없는 인물은 "지문 + 표시 이름"으로 등장해요.
  - 스테이지가 있으면 "전투 장면 넣기"로 어울리는 곳에 전투를 넣게 할 수 있어요.
  - 제목, 한 줄 소개, **이 장 요약**도 함께 만들어요. 그다음 승인 / 편집기로 불러와서 고친 뒤 승인 / 거절 + 사유 → 다시 쓰기 중에서 골라요.
- **이 장 요약**: 다음 장을 만들 때 "지금까지의 줄거리"로 들어가요. 직접 고치거나 **대본에서 다시 요약**할 수 있어요.
  - 요약이 없는 앞 장은 다음 장을 만들 때 자동으로 먼저 요약해요. 요약한 뒤에 대본을 고쳤으면 그것도 다시 요약해요.
- 새 메인 스토리는 id가 `main_01`, `main_02`…로 미리 채워져요.
- **배경 그림 생성**: 배경 제거 없이 1280×720 그림을 만들어요.
- **게임 뷰어로 미리보기**: 실제 게임의 스토리 뷰어로 재생해요.

### 게임 화면 디자인 (UI 에셋 탭)
게임 화면은 AI로 뽑은 그림 에셋을 쓰는 걸 기본으로 해요. 칸마다 그림을 뽑고, 검사해서 통과시키면 게임에 적용돼요.

| 칸 | 규격 | 게임에서 쓰이는 곳 |
|---|---|---|
| 화면 배경 8종 (홈, 뽑기, 뽑기 결과, 도감, 스토리 목록, 우편, 공지, 설정) | 1280×720 JPG | 각 화면 뒤 배경 |
| 게임 로고 | 투명 PNG (긴 변 640) | 홈 왼쪽 위 |
| 보석 아이콘 | 투명 PNG (256) | 보석 표시 전체 |
| 메뉴 아이콘 6종 | 투명 PNG (256) | 홈 오른쪽 메뉴 |

- 아이콘과 로고는 흰 배경으로 뽑은 뒤 배경을 지워 투명하게 만들어요. 캐릭터와 같은 방식이에요.
- 승인하면 작업 공간의 `assets/ui/`와 `data/ui.json`에 저장돼요. **배포 탭**에서 배포해야 실제 게임에 반영돼요.
- 그림이 없는 칸이나 파일을 못 불러온 칸은 지금의 CSS 디자인으로 보여요. **기본으로** 버튼은 칸을 비워서 CSS 디자인으로 되돌려요.
- 게임 전체 분위기 문장(설정 탭)이 모든 UI 에셋 프롬프트에 함께 들어가서 톤을 맞춰 줘요.

### 전투 데이터 (캐릭터 탭 → 전투 데이터)
- 능력치, 기본 공격 · 스킬 · 궁극기, 돌파 1~5를 **드롭다운과 숫자 칸**으로 편집해요 (게임의 `js/battle/vocab.json`으로 폼이 만들어짐). 칸마다 게임과 같은 설명 문장이 미리보기로 나와요.
- 같은 희귀도 평균보다 전투력이 `powerWarnPct`(기본 25%) 넘게 높으면 경고가 떠요.
- **AI 초안**: 설정 + 희귀도로 Gemini가 스킬 3개 + 돌파 5개를 JSON으로 제안 → 검사(오류가 있으면 한 번 더 고쳐 씀) → **승인** / **수정 후 승인**(폼에 넣고 고친 뒤 저장) / **거절 + 사유 → 다시 생성**.
- 저장할 때 검사 오류가 있으면 저장되지 않아요.

### 챕터 팩 (챕터 팩 탭)
챕터 개요 하나로 **챕터(12장) + 등장 캐릭터 + 배경 + 적 + 스테이지**를 한 번에 만들어요.
1. 챕터 번호와 챕터 개요를 적고 **구성안 만들기**를 눌러요. AI가 스토리 탭의 세계관과 지금까지의 메인 스토리를 읽고 아래를 짜요.
   - 12장 제목/개요, 어느 장에 전투가 있는지(웨이브 구성)
   - 새 캐릭터: 이름, 희귀도, 칭호, 외형 키워드, 공개 소개문, 작가용 설정 메모, 뽑기 동료인지 스토리 전용 인물인지
   - 배경(장소 이름 + 그림 설명), 적(역할: 잡몹/정예/보스, 스타일: 물리/지속 피해/치유/방어/약화)
2. 구성안을 직접 고치거나 **거절 + 사유 → 구성안 다시 만들기**를 해요. 구성안은 설정집에 저장돼서 나중에 다시 열 수 있어요.
3. **챕터 팩 만들기**를 누르면 차례대로 만들어요.
   - 캐릭터: **그림 없이** 외형 키워드와 설정만 메모된 상태 (일괄 생성/캐릭터 탭에서 그림을 뽑을 때 키워드가 자동으로 들어가요)
   - 적: 역할 × 스타일 틀로 스킬과 능력치, 스테이지: 장 번호에 맞춘 레벨(챕터 시작 + 장 − 1, 정예 +1, 보스 +3)과 보상
   - 배경: 설정집에 등록 → 일괄 생성 탭의 **스토리 배경**에 나타나요 (옵션을 켜면 바로 일괄 생성 시작)
   - 1~12장 대본: 장마다 세계관 + 챕터 전체 구성 + 앞 장 요약 + 직전 장 대본을 읽고 써요. 전투가 있는 장에는 그 스테이지의 전투 장면이 들어가요.
4. 중간에 멈추거나 오류가 나도 같은 구성안으로 다시 누르면 이미 만든 것은 건너뛰고 이어서 해요. 만든 뒤에는 스토리/적/스테이지 탭에서 고치고, 밸런스 탭에서 확인해요.
- 캐릭터의 외형 키워드와 작가용 설정 메모, 적의 메모는 **배포할 때 공개 파일에서 빠져요**.

### 배너 로테이션 (배너 탭)
- 픽업 배너에서 **자동 로테이션 픽업**을 켜면 희귀도 · 한 번에 몇 명 · 며칠마다 · 기준 시각을 정해요. 앞으로의 로테이션 순서가 미리보기로 나와요.

### 적 · 스테이지 · 밸런스
- **적 탭**: 능력치, 스킬(캐릭터와 같은 효과 엔진), 항상 켜진 패시브, 그림(올리면 긴 변 512px PNG로 `assets/enemies/<id>.png`).
- **스테이지 탭**: 웨이브(최대 6명, 적 + 레벨), 턴 제한, 클리어/첫 클리어 보상, 권장 전투력 제안, 이 스테이지를 쓰는 스토리.
- **스토리 탭 → + 전투 장면**: 스테이지를 골라 장면 사이에 넣어요. 게임에서는 스토리 안에서만 싸울 수 있어요.
- **밸런스 탭**: 팀(캐릭터 · 레벨 · 돌파)과 스테이지로 시드 1..N 자동 전투 → 승률, 평균 라운드, 캐릭터별 피해/치유/생존율. 같은 시드면 항상 같은 결과예요. 희귀도별 전투력 표, 엔진 검사, `balance.json` 편집도 여기서 해요.

### 공지 · 우편 / 일정
- 공지는 "시작 팝업"을 켜면 게임 시작 시 팝업으로 떠요. 플레이어는 "다시 보지 않기"를 고를 수 있어요.
- 우편은 기간 안에 한 번만 받을 수 있어요. 이미 공개한 우편의 id는 바꾸지 마세요.
- **일정 탭**에서 배너, 이벤트, 우편이 타임라인으로 보여요. 기간이 겹치거나 비는 구간이 있으면 경고해요.

### 배포 (배포 탭)
1. **공개 기준 시각**을 정해요. 기본값은 지금부터 24시간 뒤예요. 이보다 늦게 시작하는 콘텐츠는 이번 배포에서 **보류**돼요.
2. **검사**는 다음을 확인해요. 오류가 있으면 배포할 수 없어요.
   - 없는 캐릭터 id
   - 없는 그림 파일
   - 날짜 형식과 기간
   - JSON 문법
   - 선택지 이동 대상
3. 바뀌는 파일 목록과 패치노트 초안을 확인하고 고쳐요.
4. **배포하기**를 누르면 `data/`와 `assets/`에 반영되고 `contentVersion`이 1 올라가요. 플레이어에게는 "업데이트 내역" 팝업이 떠요.
5. 화면에 나온 git 명령을 터미널에서 실행하거나, **커밋 + 푸시** 버튼을 눌러요. 버튼은 확인 창을 거치고, 바뀐 파일만 커밋해요.
   ```
   git add data assets
   git commit -m "콘텐츠 업데이트 v2"
   git push
   ```
   몇 분 뒤 GitHub Pages에 반영돼요.

## 문제 해결
- **화면에 "모의 모드"라고 떠요**: `dev/.env`의 `GOOGLE_CLOUD_PROJECT`와 키 경로를 확인한 뒤 서버를 다시 켜요.
- **이미지 생성 요청 실패 / 404 model**: 모델 이름이 바뀌었을 수 있어요. 공식 문서에서 최신 이름을 확인해서 `.env`의 `TG_IMAGE_MODEL`에 넣어요.
- **배경 제거가 간단 모드예요**: `requirements-rmbg.txt`를 설치하고 Hugging Face 라이선스 동의와 토큰을 확인해요. 화면 위 칩에 마우스를 올리면 오류 내용이 보여요.
- **포트가 이미 사용 중이에요**: `.env`에 `TG_DEV_PORT=5051`을 넣어요.
- **ComfyUI에 연결할 수 없어요**: ComfyUI가 켜져 있는지, 설정 탭의 주소(기본 `http://127.0.0.1:8188`)가 맞는지 확인해요.
- **ComfyUI "Value not in list"**: 설정 탭에서 연결 확인을 다시 누르고, 목록에 있는 모델 파일과 샘플러를 골라요.
- **"체크포인트를 넣어 주세요"라고 나오는데 확산 모델을 써요**: 설정 탭의 **모델 불러오기 방식**을 "확산 모델 + 텍스트 인코더 + VAE 따로"로 바꿔요.
- **따로 방식에서 텍스트 인코더 오류나 그림이 깨져요**: **텍스트 인코더 종류**가 모델과 안 맞는 경우예요. 모델 배포처 예제 워크플로의 CLIPLoader `type` 값과 같은 것으로 골라요.
- **ComfyUI 그림이 이상하게 작거나 커요**: 체크포인트 종류에 맞게 해상도 기준을 골라요. SDXL 계열이면 SDXL, SD1.5 계열이면 SD1.5예요.
